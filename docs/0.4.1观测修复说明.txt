0.4.1 技能、Buff 与角色名修复

根因
旧界面的技能页只读取战斗结算，已经落盘的逐次命中没有技能汇总入口。
协议属性编号仍固定为参考版本：例如 buffs_data 1470 / ac_buffs 496；当前 Win64r 已变为 1496 / 502。
base.nickname、dungeon.is_in_boss_battle 等路径也随之变化，影响角色名与分场。

实现
按完整游戏文件 SHA256 选择属性表，验证属性表文件 SHA256。未知版本不会套用默认编号。
新表来自 2026-10-23 本机 PresetStringIndex.luac，验证常量顺序、所有 LOADK 与 SETLIST 目标后提取 10206 个名字；未执行游戏 Lua。
Buff、角色名、场景/副本状态和目标资源统一按字段名称匹配，兼容旧 Win64rh 配置。
未收到角色初始信息时，按独立 GUID 保留 Buff 状态，避免不同角色相同 Buff 键互相覆盖。
技能页汇总整个时间范围的全部通知，不受事件分页限制；结算分开显示，点击技能可查看通知时间线。
角色 ID 与名称来自服务器 Avatar.base.nickname / 对应战斗名单，日志增加来源和目标名称。未识别名称保持 null。
名称晚到时复盘动态关联，原始事件不重写；已验证名称可保存在本机缓存，后续服务器名称优先覆盖。

验证
27 项 Node 检查、46 项 Python 检查通过。
旧版与新版各通过一次真实描述符的离线采集全链测试，包含解密、角色名、命中、Buff、结算和归档。
固定当前真实属性编号用例覆盖 Buff 添加、层数修改、移除及未知 GUID 隔离。
已保存的真实会话中 367 条命中通知可完整汇总为 31 组，汇总通知数量保持 367，没有将服务器累计值重复加入。
打包引擎与 Electron 隐藏测试窗口验证技能页、技能跳转、Buff 筛选和双方角色名，测试数据与真实库隔离。
真实新战斗的 Buff/角色名称验证需用户启动 0.4.1 后进行；旧解析未保留的 Buff 数据无法事后补全。
