燕云 Logs 0.4.2 · 手动绑定与战斗复盘

启动
双击“燕云Logs.exe”，保持整个发行目录完整。无需打开浏览器。
默认不绑定进程、不抓包、不自动扫描 CLv2。
切换版本前请通过菜单“燕云 Logs → 退出”完全退出旧版；已有其他版本运行时，新版会提示尚未启动。

实时采集
1. 先启动游戏并进入角色。
2. 在“实时采集”页点“刷新”，手动选择游戏进程（显示 PID 和程序路径）。
3. 点“绑定并开始采集”。等待状态显示“采集已就绪”再开始战斗。
4. 点“打开悬浮窗”。Ctrl+Shift+F8 切换鼠标穿透；Ctrl+Shift+F9 显示/隐藏。
5. 游戏退出或重启后，重新选择进程并绑定。客户端不会自动挑选其他进程。
6. 点“停止并保留记录”结束采集。关闭主窗口也会停止本客户端的采集与解析服务。

需要本机已安装 Npcap。安装包不包含驱动。读取权限不足时，先退出客户端，手动右键选择“以管理员身份运行”。
版本校验失败时不要跳过校验；兼容配置需要更新。网络就绪不代表所有事件都完整。
支持游戏经由本地加速器转发的 IPv4 TCP 连接；这类连接使用 Npcap 回环接口，仍只按手动绑定的游戏进程筛选。
游戏改用 KCP 时，会读取所选游戏当前传输类型和远端地址，自动改用 UDP/KCP 解析；支持本次已验证的 UU IPv4 转发封装。
KCP 初始化与正式采集共用一条捕获，按片段序号重排、去重；缺口、冲突或会话变化时停止解码并重新校验。
UDP 转发只按所选游戏的真实远端地址筛选，并须通过该游戏会话的唯一解码校验；不会把加速器进程当作绑定对象。
“没有收到游戏数据”与“协议校验失败”分别提示。游戏进入角色后仍反复恢复时，可查看 captures/sessions 中对应初始化记录。
IPv6-only 连接会明确提示暂不支持；权限错误、无已建立连接、游戏版本不兼容分别提示。

版本适配检查
如果已识别连接但提示游戏版本尚未适配，在发行目录中右键“检查当前游戏版本.cmd”，选择“以管理员身份运行”。
工具只检查先前在客户端手动选中的同一游戏进程；游戏重启后需先重新绑定。
只读保存主程序代码段和只读数据段，用于核对新版本的解析位置；不读堆、不修改游戏、不自动上传。
资料位于 captures/compatibility。检查工具不会自动运行；生成资料本身不表示已完成版本适配。

战斗复盘
“技能观测”实时汇总已收到的命中通知，显示次数、通知累计、首次/末次时间；点击技能查看对应事件。
战斗结束后的服务器技能结算单独展示，不能与通知累计相加。通知次数不表示施法次数。
Buff、名称、战斗状态使用与游戏程序版本对应的属性编号表，包含当前 Win64r 版本。
已识别角色的通知日志会写 sourceActorName / targetActorName，并保留 actor ID 关联。
名称晚于事件到达时，复盘通过 identities.json 回填名称；未收到名称的角色仍保留未知状态。
名称来源包括角色快照、带角色 ID 的属性更新、队伍成员名单及已解析的战斗资料，始终按角色 ID 对应。
已收到的名称保存在本机 captures/identity-cache.json，之后的会话会复用；新名字到达时更新缓存。
角色已登录后才开始采集，可能错过名称快照；保持采集后切换场景或进入队伍，有助于收到新的角色资料。
旧日志中已保存的技能通知可以重新汇总；旧解析漏掉的 Buff 没有保留原始数据时无法补回。
“捕获记录”列出完整会话和已识别战斗，可查看队伍累计值、技能结算、逐次通知、Buff 变化。
“解析已有捕获目录”支持本软件及参考软件的 capture、包含 sessions 的记录目录。
目录通过本地索引读取，不移动或改写导入的原始记录。
“本地 CLv2”进入原有详细复盘：手动导入 .bin/日志压缩包，或点击扫描已有游戏日志。
此页保留技能阶段、Buff 覆盖、事件、笔记、多视角合并；“复盘统计窗”展示所选日志。

悬浮窗
燕云专用界面仅显示输出、治疗、承伤字段、连接状态及时间。
齿轮按钮调整背景透明度和字体；拖动标题栏移动窗口。
原版 FF14 职业图标、职业筛选、宠物合并、直击/暴击、ACT 连接设置均不进入发行包。
使用窗口化/无边框游戏模式便于显示独立置顶窗口。
悬浮窗右上角自动显示开战计时（显示到 0.1 秒），无需手动按开始。
“战斗计时”依据收到的服务器开战状态；没有开战状态时，累计值重置并产生输出后显示“估算计时”。重置后的准备等待不计入。
结束信号到达后停表；服务器给出正式时长后显示“服务器结算”，输出/治疗每秒数值同时校准，并保留到下一次开战。
鼠标停留在计时区域可查看计时来源；正式时长的完整数值用于计算，不使用显示时截取的小数。
中途绑定且没有开战依据时显示“开战时间未知”；停止采集或失去数据更新时计时暂停。战斗中仍可能有接收延迟，最终以收到的服务器时长为准。

数据
菜单“打开战斗归档”查看实际归档路径；“打开记录目录”进入 captures。
旧 CLv2 战斗库继续保留。captures/sessions 下保存各会话的原始捕获、解码事件和分段战斗。
不自动上传数据。源程序配置与连接状态包含本机会话信息，不是可公开的测试样本。

数值范围
累计伤害来自服务器统计，单次通知、结算是其他视图，不相加。
网络事件时间为接收时间，不能当作服务器精确执行时间。
技能通知不能代替完整施法记录；Buff 添加/移除部分是候选语义，队友私有状态与完整覆盖尚未验证。
时长未知显示“—”；缺失值与真正的 0 分开。未启用 rDPS。
本地 CLv2 的“观测每秒”仍不是完整全队 DPS。
