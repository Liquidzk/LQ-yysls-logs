# 燕云 Logs 客户端使用说明

## 安装与启动

1. 从[最新版下载页](https://github.com/Liquidzk/LQ-yysls-logs/releases/latest) 下载 `win-x64.zip` 客户端压缩包。
2. 完整解压，双击 `燕云Logs.exe`。请保留同目录下的其他文件。
3. 首次实时采集前，按下面的步骤安装 Npcap。仅复盘已有捕获记录或原生 CLv2 日志，无需安装 Npcap，也无需绑定游戏。

启动后不会自动绑定游戏。原生日志的自动扫描默认关闭，开启后会记住设置。切换客户端版本时，先通过菜单“燕云 Logs → 退出”完全退出旧版，再打开新版；游戏无需重启。

### 更新客户端

从 0.4.21 起，可在客户端内更新：

**仓库更名后的首次升级**：0.4.23 及更早版本可能提示“更新附件信息无效”，请先从[最新版下载页](https://github.com/Liquidzk/oh-my-yysls-logs/releases/latest)手动下载并完整解压新版，退出旧版后启动新版。0.4.24 已适配新地址，后续可按以下步骤更新。

1. 打开“设置 → 客户端更新”，或菜单“帮助 → 检查更新…”。
2. 点击“检查更新”，查看是否有新的正式版本；“查看更新说明”打开该版本的 GitHub 页面。
3. 点击“下载更新”。下载时显示进度，可以继续复盘，也可以取消后重试；下载完成会校验文件并准备更新，不会自动重启。
4. 方便时点击“重启更新”。客户端先停止采集并保留记录，再退出、替换程序并重新打开。更新后仍需手动绑定游戏。

更新会沿用原程序位置、设置、收藏和战斗记录，无需重装 Npcap，也无需重启游戏。更新使用完整客户端包；下载缓存位于用户设置目录下的 `updates` 文件夹。后续下载会清理已结束的旧更新缓存。替换前备份受影响的程序文件；替换失败或新版未能完成启动时会尝试恢复旧版。

若检查或下载失败，可检查 GitHub 连接后重试。若程序目录不可写，请退出客户端，以管理员身份运行后再更新。正在恢复或提示恢复失败时，请保留更新缓存。

**0.4.20 及更早版本需要先手动升级一次**：从[最新版下载页](https://github.com/Liquidzk/LQ-yysls-logs/releases/latest)下载 `win-x64.zip`，通过旧版菜单“燕云 Logs → 退出”完全退出，再将新版完整解压到新文件夹并启动，更新桌面快捷方式。不要只替换单个 exe 文件。

同一 Windows 用户下，手动更新也会沿用目录设置、收藏和默认位置的记录。默认采集目录为 `%APPDATA%\LQ-yysls-Logs\data\captures\`；自定义目录需保持可访问，如果它在旧程序文件夹内，请保留其中的记录。

### 安装 Npcap

Npcap 提供实时采集所需的抓包驱动，客户端压缩包未附带此驱动。一般安装一次即可，升级燕云 Logs 无需每次重装；若之前安装 Wireshark 时已装好 Npcap，可直接尝试开始采集。客户端已附带 TShark 采集组件，无需另外安装 Wireshark。

1. 打开 [Npcap 官网](https://npcap.com/#download)，在下载区点击 **Npcap installer**，下载 `npcap-版本号.exe`。不要下载 SDK、源码或调试文件，也不要用旧 WinPcap 代替。
2. 若正在更新已有 Npcap，先停止采集并退出燕云 Logs、Wireshark 等正在使用抓包驱动的程序。
3. 运行安装程序，允许 Windows 的管理员权限提示；阅读许可后，按安装器提示继续。
4. 安装选项一般保持默认即可，具体含义见下表。
5. 安装完成后，若提示重启 Windows，按提示重启；否则完全退出旧客户端，再重新运行 `燕云Logs.exe`。
6. 手动启动游戏、进入角色，刷新并选择游戏进程，点击“绑定并开始采集”。状态显示“采集已就绪”后即可使用实时统计。

| 安装选项 | 本客户端如何选择 |
| --- | --- |
| 仅允许管理员访问（`Restrict Npcap driver's access`） | 一般保持默认；若已勾选，以管理员身份启动燕云 Logs |
| 无线原始帧／监听模式（`raw 802.11`） | 无需勾选；电脑使用 Wi-Fi 联网也不需要这个选项 |
| WinPcap 兼容模式（`WinPcap API-compatible Mode`） | 本客户端不依赖此选项，一般保持默认；兼容模式会替换已有旧 WinPcap，仍需保留旧驱动时按安装器说明选择 |
| 旧式回环适配器（`legacy loopback`，部分版本可见） | 无需额外启用；当前 Npcap 自带回环流量采集能力 |

使用 UU 等本地转发加速器时，客户端会按连接情况选择回环采集接口，不需要手动添加虚拟网卡。若提示“缺少回环采集接口”或“没有可用抓包网卡”，先退出客户端，检查 Npcap 安装是否完成，必要时使用官方安装器更新并按提示重启。

安装抓包驱动与读取游戏进程是两项权限：即使 Npcap 已安装，若客户端仍提示游戏读取权限不足，需退出客户端，再右键 `燕云Logs.exe` →“以管理员身份运行”。

安装选项以 [Npcap 官方用户指南](https://npcap.com/guide/npcap-users-guide.html)为准。

## 原始抓包与保留设置

在客户端设置中选择“原始抓包保留”，可设置 7 天、30 天、不限期限或采集结束后清理，以及 128 MB、512 MB、2 GB 或不限总空间。默认保留 7 天、总计不超过 512 MB；两个条件任一达到时，优先清理最旧的已结束原始抓包。修改后下次开始采集时生效。

原始抓包自动压缩，供排查和重新解析使用。清理在开始及停止采集时执行，当前会话暂不受空间上限约束；只处理新版明确标记的原始抓包，不删除旧版原始文件、战斗事件、结算、设置和收藏。被清理的记录仍可复盘，但无法再从原始消息重新解析。排查问题期间可选择“不限期限／不限空间”，结束后再恢复默认设置。

## 实时采集

1. 手动启动游戏并进入角色。
2. 在“实时采集”页点击“刷新”，根据程序路径和 PID 选择游戏进程。
3. 点击“绑定并开始采集”，等待状态显示“采集已就绪”。
4. 点击“打开悬浮窗”，即可在游戏中查看实时统计。
5. 结束记录时点击“停止并保留记录”。关闭主窗口或退出客户端也会停止采集，已保存的记录保留。

游戏退出或重启后，需要刷新进程列表并重新绑定。若提示无读取权限，退出客户端后右键选择“以管理员身份运行”，再手动绑定。

## 客户端设置与保存目录

点击主窗口右上角“设置”，或实时采集页的保存路径，打开客户端设置。

- “采集保存目录 → 选择文件夹…”指定新采集的保存位置，自动记住，下次启动继续使用。新安装默认是 `%APPDATA%\LQ-yysls-Logs\data\captures\`；已有自定义目录继续保留。
- 未采集时立即生效；正在采集时，当前会话仍写入原目录，点击“停止并保留记录”后切换。不会自动重新绑定。
- 旧文件保留在原位置，捕获记录列表继续展示旧目录中的记录；原目录所在磁盘需要保持可访问。
- “打开文件夹”打开设置中的目录。实时采集页“打开记录目录”打开当前会话实际写入的目录。
- “游戏原生日志”可选择游戏目录并开关自动扫描，与网络采集的保存位置分别设置。

## 悬浮窗

### 统计与外观

- 点击“输出”“治疗”“承伤”切换统计项目，查看队员累计值和每秒数值。
- 拖动标题栏移动窗口；悬浮窗保持置顶，建议配合游戏的窗口化或无边框模式使用。
- 点击齿轮调整背景透明度、文字大小和 Boss 血量显示，设置会自动保存；“恢复默认”可重置外观。
- 点击 `↗` 返回主窗口复盘，点击 `−` 隐藏悬浮窗。

### 快捷键

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl+Shift+F8` | 切换鼠标穿透；开启后鼠标操作会落到下方游戏窗口 |
| `Ctrl+Shift+F9` | 显示或隐藏悬浮窗 |
| `Ctrl+Shift+F10` | 实时悬浮窗显示时，收藏当前采集会话中最近结束的战斗 |

需要点击悬浮窗按钮时，先关闭鼠标穿透。收藏快捷键被占用时，设置中会提示，可改用悬浮窗的 `☆` 按钮。

### 战斗计时

计时自动开始和结束，无需手动按表。胜利或战斗结束通知到达后先停表，收到匹配的服务器结算时长后再校准，每秒统计同时更新。

| 状态 | 含义 |
| --- | --- |
| 战斗计时 | 已收到开战依据，正在计时 |
| 估算计时 | 缺少明确开战通知，以累计统计变化估算起点 |
| 已胜利 · 待校准 | 已收到胜利通知，等待服务器结算时长 |
| 服务器结算 | 已使用服务器给出的战斗时长 |
| 开战时间未知 | 中途绑定等情况下，缺少本场起点 |

鼠标停留在计时区域可查看来源。停止采集或失去数据更新时计时暂停；已结算的成绩保留至下一次开战。

### Boss 血量

在齿轮设置中选择“百分比”或“真实数值（当前／上限）”；真实数值可以使用原始单位或“万”。

愁铃客的肉体、灵魂分别显示两条血量，并显示百分比差。鼠标停留在血条上可查看完整数值。未收到完整血量时显示等待；采集停止或连接中断时保留末次观测。

## 捕获记录与战斗复盘

点击“捕获记录”，在左侧选择记录：

- **战斗**：一场已识别的战斗，适合查看成绩和时间线。
- **完整采集会话 · 包含 N 场战斗**：整次采集的入口，可包含多场战斗以及战斗前后的观测。
- **完整采集会话 · 未分段观测**：已有事件，但尚未识别出独立战斗边界。

仅有初始化信息的空会话不会列出。点击列表旁的刷新按钮可重新读取记录；“解析已有捕获目录”可添加本软件或参考软件的 `capture` 目录、会话目录或包含 `sessions` 的目录，导入不会移动原始文件。

| 页面 | 用法 |
| --- | --- |
| 队伍统计 | 查看服务器累计输出、治疗及每秒统计 |
| 技能观测 | 多选本场角色，查看各技能的伤害占比、整场 DPS 贡献和动作 DPS；可按技能名称／编号搜索，点击技能查看对应事件 |
| 原始事件 | 按角色、事件类型和名称／编号筛选，翻页查看；点击一条事件查看详细字段 |
| Buff 观测 | 查看 Buff 添加、更新、移除等通知，按角色和编号筛选 |
| 战斗时间线 | 对照 DPS、Buff 覆盖和动作顺序，操作见下节 |

## 战斗时间线

先选择一场战斗，再点击“战斗时间线”。如果选中完整会话，页面会提示先选择具体场次。

### 技能观测与 DPS 贡献

在“技能观测”勾选一位或多位本场角色；“全选”和“清除”可快速调整范围。这里按施放者筛选，不会把打到所选角色身上的伤害计入其输出。角色选择同时作用于贡献明细、命中明细和服务器技能结算；切换战斗后重置为本场全部角色。

- **整场 DPS 贡献**：该角色该技能的伤害累计 ÷ 整场时长，同一技能对多个目标的伤害合并。优先使用服务器结算中的伤害分类；治疗和承伤不计入。未能归属到技能的结算差额单列为“未分配到技能”。
- **占所选伤害**：该行伤害占所选角色伤害总和的比例。搜索技能仅隐藏不匹配行，不改变占比分母。
- **动作 DPS**：命中明细中的累计数值 ÷ 同一角色该技能各次动作的累计持续时间，不计动作间空档。这与整场 DPS 贡献使用不同的时长，不能将动作 DPS 各行相加作为全场 DPS。

尚未收到服务器技能结算时，贡献区标为“命中观测 · 待结算”，临时统计向自身及本场队友以外目标的命中数值。这些通知仍可能不完整或未分类；命中明细中也可能包含治疗，不应作为完整结算伤害。缺少必要数据时显示 `—`。

### 命中与结算核对

在“技能观测”中展开“命中与结算核对”。按所选角色显示每个对外目标的结算伤害、命中观测、待核对差额和单独的伤害飘字。点击“技能归属”查看每个编号的结算与观测差异。

正差额表示该范围内的命中观测较少，负差额表示观测较多。差异可能来自接收时间边界、未下发或未解析事件，以及附加伤害使用不同技能编号；不能直接当作丢包量。核对不会猜测补入命中，也不会用伤害飘字强行填平差额。结算统计和 DPS 总榜继续以服务器数据为准。

### DPS 曲线与时间范围

在“DPS 查看角色”勾选任意多位角色，每人显示一条独立曲线；“全队 DPS”可单独开关。“全部角色”和“清除角色”只改变个人曲线，不影响全队开关。平滑窗口可选 1、3、5、10 秒。移动鼠标可同时查看所选角色在该时间点的数值。

DPS、Buff、动作和事件筛选只列当前战斗的角色；历史名称缓存仅用于补全名字。技能命中明细中的动作 DPS 使用“伤害累计 ÷ 同一角色该技能各次动作的累计持续时间”，不计两次动作之间的空档，也不使用首次到末次命中的跨度。部分已知时长显示“至少 N 秒”，动作 DPS 仍用伤害累计除以已确认的 N 秒，未知部分的时长不计入分母。缺少伤害记录、未取得时长或持续时间为零时显示 `—`。

输入起止秒数并应用可查看局部，点击“全场”恢复。下方覆盖率和动作轨道使用同一时间范围。

### 添加和排列时间线

1. 展开“选择加入时间线组的内容”。
2. 选择“队员 Buff”“Boss Buff／Debuff”“玩家动作”或“战斗事件”。
3. 按角色／目标、名称或编号筛选，勾选所需行加入组中；批量勾选与取消只作用于当前筛选结果。
4. 拖动每行左侧的 `⠿` 调整顺序，四种类型可以混排。也可聚焦手柄后按 `Alt+↑`／`Alt+↓` 移动。
5. 取消勾选可移除单行；“清空时间线组”移除全部行，“恢复默认选择”恢复组内默认内容。

默认加入各玩家动作，以及已观测到的增伤 霖 `#1058032`、增伤（阴阳）`#98752`、崩解 `#10245332`；Boss 效果按需勾选。愁铃客肉体与灵魂可分别选择。

布局、DPS 曲线选择和动作明细角色选择按战斗保存，最多保留 15 场布局。顶部 DPS 角色选择、时间线组和底部明细的角色选择相互独立。

### 查看覆盖和动作

- **Buff 覆盖条**：右侧百分比按当前时间范围计算，重叠来源只计算一次。点击区间查看接收者、来源、层数和起止时间。条纹表示起止边界不完整。
- **玩家动作条**：实色表示已观测到起止的动作，条纹表示边界不完整；命中通知单独保留。点击动作条查看时长与结束依据，点击通知点查看附近事件。
- **战斗事件轨道**：按角色勾选，查看治疗飘字、防御、卸势、死亡、复活和受击反应等时间点。点击查看来源、目标及技能。治疗飘字暂未区分有效治疗与过量治疗，伤害飘字单独保留，不与已有命中相加。
- **组内动作筛选**：可选择施放与命中、只看施放或只看命中，也可搜索技能。

### 动作次序明细

在最下方勾选任意多位角色，查看各自依次的技能、开始／结束时间、动作时长和前次间隔。明细的技能搜索与组内动作搜索相互独立。

切换为“待复查间隔”可按间隔从长到短查看，并设置最小秒数。点击“查看附近”会缩小上方时间范围，并将对应玩家动作加入时间线组。

动作时长表示服务器同步中观测到的占用区间，不等同客户端动画的前摇或后摇。空档需结合走位、机制、不可攻击阶段和记录缺失判断，不能直接当作散步时间。

## 收藏战斗

捕获记录及本地 CLv2 列表中的 `☆`／`★` 可收藏或取消收藏；勾选“只看 ★ 收藏”筛选记录。捕获战斗详情也可使用“收藏战斗”按钮。

实时悬浮窗显示时，按 `Ctrl+Shift+F10` 或点击悬浮窗 `☆`，可收藏当前采集会话中最近结束并保存的战斗。重复操作保持收藏，不会取消；界面会提示成功或未能收藏的原因。

## 本地 CLv2 日志

### 导入、扫描与选择

点击顶部“本地 CLv2”，无需绑定游戏即可复盘。

- 点击“导入日志”，选择游戏保存的 `.bin` 文件或 `.zip` 日志包；可多选，单个文件上限为 64 MB。
- 点击左侧醒目的“选择游戏目录…”，选择游戏安装目录、`LocalData` 或 `ClientLocalLog` 文件夹。选择后会自动定位日志并立即扫描，无需重启客户端。
- 勾选“自动扫描新日志”后，每 10 秒检查新增或更新的原生日志；下次启动继续使用这个设置。未勾选时，点击“扫描”手动更新。游戏尚未写完的文件会等到写完再归档，重复文件不会反复新增记录。
- 原生日志与实时采集共用内置技能、Buff、场景字典及手动名称。更新客户端后，旧记录也使用新版字典，无需重新导入。
- 在左侧按日期、场景名称或编号搜索并选择战斗。

### 分析、播放与笔记

选择“观察对象”和分析区间，在“战斗时间线”“技能复盘”“Buff 覆盖”“伤害与治疗”“事件记录”之间切换。点击技能释放记录，可查看当时的 Buff、来源、层数和技能阶段。

拖动底部时间滑块查看当前状态、多人同期快照及最近事件；点击播放按钮按所选速度推进。输入复盘笔记并点击“添加标记”，即可将笔记保存在当前时间点。

点击“复盘统计窗”查看所选日志的统计；它展示的是本地复盘数据。

### 合并视角与导出

在列表中勾选同一场战斗的 2～12 份日志，点击“合并勾选视角”。设置各视角的时间偏移后打开合并复盘，正数表示向后移动该视角。

点击“导出日志包”导出当前报告涉及的原始日志。多视角同时间戳的先后顺序与重复回报可能存在不确定性，应结合事件详情核对。

## 转换为 YYLogs 上传包

客户端压缩包已附带独立转换器，无需另装 Python 或 Node.js。打开程序目录下的 `resources\YYLogs-Converter\LQ-YYLogs-Converter.exe` 即可使用；仅转换已有记录无需启动游戏或安装 Npcap。

1. 若要转换当前会话，先在客户端点击“停止并保留记录”；已经结束的会话可以直接转换。
2. 打开转换器，选择采集保存目录，点击“扫描记录”。支持选择整个 `captures`、`sessions` 或单个会话目录。
3. 勾选所需会话，选择输出目录，点击“开始转换”。工具会记住目录，下次打开继续使用。
4. 在输出目录取得 `.yylogs` 文件和转换报告。每个会话生成一个包，可能包含多场战斗；在兼容的分析工具上传这个文件即可，无需再次压缩。

转换器只读取原记录，不会自动上传。详细步骤、字段说明和常见问题见同目录 `README.md`。客户端内更新会同步更新附带的转换器；更新前请先关闭转换器窗口。

遇到新版游戏记录的协议标识不兼容时，请使用附带的 1.1.1 或更新版本转换器重新转换原记录；已导出的文件不会自动更新。

新版采集补充属性变化、Buff 触发资源计数、资源状态和辅助数字提示，供目标分析器重放、估算 rDPS。转换报告会说明归因输入是否完整；未下发的队友私有状态、未知属性和旧记录缺失的数据不会凭空补齐。rDPS 由目标分析器计算，本客户端原有复盘和统计方式保持不变。

## 名称查询

在捕获记录界面点击右上角“名称表”，选择 Buff、技能／动作、场景或 NPC 模板，按名称或原编号搜索。可筛选已映射、待恢复或客户端未命名的条目，并查看来源。

本地 CLv2 页使用“名称映射”入口。未取得名称的条目保留原编号；`#98752` 的复盘显示名为“增伤（阴阳）”。

## 记录保存与数据含义

点击“打开记录目录”进入网络采集的 `captures` 目录；菜单“燕云 Logs → 打开战斗归档”打开应用数据目录。`captures/sessions` 保存各次采集及其分段战斗，收藏独立保存。

压缩事件文件为 `.jsonl.ylz`，选择所在捕获目录即可复盘，无需手动解压或额外安装压缩工具；旧 JSONL 记录也可读取。客户端不会自动上传记录。

复盘时请区分这些数值：

- 服务器累计统计、逐次通知和技能结算是不同视图，不能相加。
- 网络时间线使用本机接收时间；命中次数不等于施法次数，延迟命中可能在动作结束后到达。
- Buff 未观测到不等于没有，队友私有状态可能不完整；旧记录缺失的事件不会凭空补出。
- 未知数值与实际的零分开显示；本地 CLv2 的“观测每秒”不代表完整全队 DPS，目前未提供 rDPS。

## 常见问题

| 情况 | 操作 |
| --- | --- |
| 未检测到 Npcap | 安装官网的 Npcap installer，然后完全退出并重新打开客户端；SDK 或单独复制 DLL 不能代替安装驱动 |
| 没有可用抓包网卡／缺少回环采集接口 | 检查 Npcap 是否安装完成；退出采集程序后更新驱动，若安装器要求重启 Windows，先完成重启 |
| 安装 Npcap 时提示文件正在使用 | 先停止采集并退出燕云 Logs、Wireshark 等使用抓包驱动的程序，再继续安装 |
| 找不到进程或读取权限不足 | 确认游戏已启动，刷新列表；需要时退出客户端并以管理员身份运行后重新绑定 |
| 游戏重启或连接变化 | 游戏重启后手动重新绑定；连接变化时等待重新校验，查看状态栏原因 |
| 等待采集恢复、没有游戏数据或协议校验失败 | 确认已进入角色，查看状态栏具体原因；记录目录中的初始化资料可用于排查 |
| 提示游戏版本尚未适配 | 先手动选中游戏进程并尝试绑定，再以管理员身份运行发行目录内的“检查当前游戏版本.cmd”；结果保存在 `captures/compatibility`，需后续适配 |
| 角色名或 Boss 血量缺失 | 保持采集后切换场景或重新进入副本，等待完整实体快照；已遗漏的历史数据不保证能补回 |
| 时间线提示选择战斗 | 从完整采集会话中选择具体场次 |
| 收藏快捷键无效 | 确认实时悬浮窗正在显示且当前会话已有结束战斗；快捷键冲突时使用 `☆` 按钮 |
| 切换版本后仍是旧客户端 | 从菜单完全退出旧版，再启动新目录中的程序 |
